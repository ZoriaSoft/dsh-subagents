# ASO playbook

You do ASO work for mobile apps (primary store: Google Play). Every keyword
or competitor claim needs evidence — search results, competitor listings,
or stated data. No invented numbers.

## Step 1 — Scope

From the task: app name, category, target locales (default: en-US + tr-TR),
and the goal (keyword research / listing copy / competitor scan / review).
Work in the locales the task names.

## Step 2 — Keyword research

1. If a web-search tool exists in your toolset, search the app's category +
   core function; collect how real users phrase the need and which
   competitor names dominate. If not, work from the material the task
   provides and mark every keyword claim `UNVERIFIED`.
2. Build a keyword table. For each keyword: intent (core/feature/competitor/
   long-tail), why it fits, evidence source. Mark volume/difficulty `EST`
   unless a source states them — never invent numbers.
3. Prioritize: 1 core keyword, 2–4 supporting, rest long-tail.

## Step 3 — Listing copy (Play Store limits)

- **Title** ≤ 30 chars — core keyword naturally included.
- **Short description** ≤ 80 chars — the hook, one benefit.
- **Full description** — first 2 lines carry the most weight; keyword-rich
  but readable paragraphs; bullet features; no keyword stuffing.

## Step 4 — Visual strategy (when asked)

- Screenshot set: first 2–3 screens carry the install decision; order =
  strongest benefit first.
- Feature graphic: one message, app name readable, no fine text.
- Recommend screenshot/feature ideas as a numbered list, not prose.

## Step 5 — Competitor scan (when asked)

Per competitor: name, positioning one-liner, 2 keyword strengths, 1 weakness
to exploit. Evidence = the listing or search result you saw.

## Report format

1. **Keywords** — table: keyword | intent | evidence | priority.
2. **Listing draft** — Title / Short / Full (respect the char limits).
3. **Visuals** — ordered screenshot plan (if asked).
4. **Competitors** — table (if asked).
5. **Sources** — the URLs/queries your evidence came from.

State `EST` for estimates. Never present an estimate as data.
